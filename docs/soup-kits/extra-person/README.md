# 多出来的人，缺席的人

面向 5 人（1 汤主、4 侦探）的图片海龟汤。目标时长 12–20 分钟，尚未经过真人盲测，不承诺实际难度或耗时。按经典全景重影机制重新编写了“六个人影、四个身份、五名成员”的双层谜题。无死亡、血腥或灵异。

## 直接使用

以下按默认的清晰文字说明；标题栏可切换低调文字，流程与材料相同。

1. 五人加入 A5 房间，房主在“本题汤主”选择准备出题的人，再点“请汤主准备题目”。
2. **只把 `多出来的人-题材包.json` 交给指定的汤主**。包中含完整答案，不要发到全员群。
3. 汤主选择“导入题材包”，选择 JSON。确认导入，检查谜面，再点“发布谜面，开始提问”。图片需现有 V1.12.2 存储已配置；指定汤主需 V13 增量迁移。
4. 大家在“当前题目”打开谜面图片，先观察约 30 秒，再自由讨论并排队问是非问题。汤主直接回答页面顶部的队首，不必切换工作表。
5. 若无进展，约在第 5、9、14 个有效问题后，汤主预览并发布下一条提示。玩家推进顺利可以不发；不要机械地等到指定问数。
6. 侦探选择“完整还原”，用“提交还原”说清多出来的原因与缺席者身份。汤主判成功后，所有人自动看到答案，再展开“结局图片”对照幕后路线复盘。房主可指定同一人或另一人准备下一题。

老版本也能玩：复制 `source.json` 的 surface / bottom / keyFacts / boundary 到对应输入框；上传 01 为汤面图、03 为汤底图。02 仅在第二阶段作为公共证据发布。不会自动把新操作部署到在线站点。

## 设计与节奏

开场矛盾：同一张合影，为什么既“多了一个”，又“少了一个”？人影数量与成员身份数量不是同一口径。

第一层：图中同一红衬衫人物有一致的面孔、绿手环与鞋子，手势从 1 变成 2、3。允许玩家迅速识别重复；题目并不靠隐藏长相拖时间。

第二层：如果没有拍后复制，怎样在一次成片中重复出现？补充全景拍摄图，让不熟悉摄影的人也能理解“照片左右两侧不一定同时拍摄”。

第三层：解释重复还不够。六个人影只有四个不同身份，现场还有第五位组员——一直持机的小林。这是摄影师的缺席，不是有人被删掉。

笑点落点：阿程抢了三个位置，却没替摄影师留下一个。揭晓后可口头挑战“下次怎样让五人都入镜且每人只出现一次”，不要把它作为答题必需条件。

## 图片清单与事实边界

- `01-surface.png`：开场合影，六个人影，顺序为阿程 / 小何 / 阿程 / 老周 / 小麦 / 阿程。
- `02-evidence.png`：第 9 问附近使用的手机全景拍摄示意；远景虚化不作为人物站位证据。
- `03-reveal.png`：仅揭晓时展示的幕后示意，五位真实成员及绕到镜头外的跑动路线。箭头用于解释，不是现场真实粉笔痕迹。

三图均由内置 imagegen 生成，是虚构场景复现，不是真实照片或现场鉴定材料。已人工目视核对开场六个人影、三次红衣人物、1/2/3 手势与结局五个真实人物；精细像素差异、建筑窗户数量、光影、画面边缘等不作为谜题线索。最终提示词见 `image-prompts.txt`。严禁把“没有后期增删人物”误答为“相机没有做任何自动拼接”。

## 汤主判定示例

- “是一个人跑到不同位置被拍了好几次。”→ 还差一点：还要解释拍摄方式，以及谁缺席。
- “摄影师当然没入镜。”→ 还差一点：还要解释多出的完整人影。
- “全景镜头慢慢扫过去，红衣人绕到镜头外换位置，出现三次；另外三人各一次，拿手机的第五人没入镜。”→ 还原成功。
- “AI复制了人”“三胞胎”“镜子反射”→ 还原错误。
- “是不是相机自动把不同时刻扫到的画面合成了全景？”→ 是。
- “具体是哪款手机、用了多少秒？”→ 无关。不编造额外设定。

## 试玩验收

先让没看过汤底的 4 人玩一次，记录首次识别重复人物的问数、识别全景的问数、是否自发想到摄影师、是否需要第三提示。若 5 问内解完，作为热身题；若全景机制始终卡住，提前发第二张图，而不是加隐蔽限制。当前已完成的是内容逻辑复核与应用自动化检查，真人趣味性仍待试玩。

## 文件与操作边界

`source.json` 保存文本与相对图片名，用 `node scripts/pack-soup-kit.mjs` 生成可导入的单文件 JSON。包和图片在 docs 内，不进入应用的公共资源目录或前端打包导入。

题材包导入后，汤底仍提交到现有私密表；未公开提示只缓存在汤主当前标签页的 sessionStorage，按房间、局次、题次、玩家隔离。刷新同一标签页可恢复；换设备或关闭标签页后不保证恢复阶段提示，可按本材料手动发布。已公开提示从房间状态判定，避免刷新后再次发送。

图片沿用现有 24 小时签名链接。适合当天短局；不支持长期保鲜或自动续签。V13 提供指定汤主的新增函数，需部署者先执行增量 SQL 与只读核验，再发布前端。已完成 V13 核验的环境升级 V1.13.2 只需更新前端。题材包本身不改变云端数据或权限。
