01

四款游戏，各有明确的位置

以下为当前实现与阶段判断，不用未经定义的“完成百分比”代替验收状态。

A2

谁是卧底

3–10 人 · 隐藏身份与推理 · /undercover/

维护与回归

发词、空白牌提示、描述投票、爆灯与指认、暂退退出、自动推进、换词重开已实现。界面持续向紧凑、清楚的表格操作收敛。

接下来：重点回归特殊身份、多人同时操作和断线恢复，保持玩法稳定。

A3

提示大王

2–8 人 · 联想与创作 · /clue/

优先打磨

默认“普通 + 角色扮演”；120 题、三种模式。一批提示最多猜三次，失败也评分；支持 1–4 分、同行点赞和双榜单。

判断：已有明确正向试玩反馈。优先改善题目与角色搭配，不急着增加流程负担。

A4

离谱法堂

2–8 人 · 圆谎与表达 · /court/

简易流程保留

当前使用 V6：案件、首次陈词、证据突袭、补述、双项评选。三轮制；两段写作各 5 分钟，投票 2 分钟。

注意：V7 质询与招式按试玩反馈主动停用，不是漏开发；正文 SPEC 尚需同步。

A5

汤底侦探

3–10 人 · 合作解谜 · /soup/

候选版待实测

汤主轮换、私密资料、独立草稿、轮流行动、判定、20+5 问、两次提示、揭晓与反馈均已实现。本次补齐保存与轮次保护。

未完成：云上多人验收与题卡盲测。20 张题卡仍为 pilot，不能称为已审核题库。

03

本次交付解决了什么，哪些还没有证明

已完成的修正与验证

  • 草稿不被旧响应覆盖顺序保存、临时断网保留文字、版本冲突显式选择。
  • 正式操作和反馈有轮次保护拒绝上一题延迟写入；重复请求保持幂等。
  • 阅读与结束流程更完整汤主长资料不再只显示 4 秒；多行输入、帮助返回、行内确认。
  • 120 项自动测试全部通过含 A2/A3/A4 回归，以及 3/5/8/10 人本地 PostgreSQL 流程测试。
  • 静态构建与类型、代码检查通过默认 npm run build 生成完整目录和四个游戏页面。

仍需真实场景验证

  • 多连接并发与断线恢复

    本地 PGlite 是单连接环境，不能证明云端多个浏览器同时操作一定正常。

  • 实际页面体验

    需在部署站检查长内容、切换工作表、窗口失焦、重新加入和下一碗。

  • 题卡是否真的好玩且公平

    A5 每题至少 3 次盲测；普通题至少 2/3 试玩组在 20 问内解决，好玩度与公平度平均不低于 4/5。

  • 发布前后的版本一致性

    确认前端提交、数据库版本、测试结果属于同一次交付，不混用旧页面验收。

04

影响后续迭代的四个问题

优先

文档落后于代码

A4 SPEC 仍以 V7 为主，A3 部分记录仍写“等待迁移”。后续应明确区分当前规则与历史方案，避免根据旧文档重新走偏。

优先

题库质量闭环未完成

A5 部分题材反转相似；A3、A4 也需持续淘汰难理解、难发挥或重复感强的内容。数量达标不代表趣味性达标。

待办

依赖与旧接口维护

最近依赖审计记录 11 项告警（10 high、1 low），尚待兼容升级验证。历史 RPC 保留但需梳理权限；A2 仍以熟人正常游玩为信任边界。

待办

两套构建增加成本

CloudBase 默认打包已统一为 Next 静态导出；旧 Vinext 可选链路存在跳过路由和 Windows 退出异常，不用于本次部署。
